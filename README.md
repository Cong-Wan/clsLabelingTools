# clsLabelTool 图片分类标注工具

局域网图片分类标注工具：Python 后端（FastAPI）+ 原生 HTML/JS/CSS 前端（零框架、零 CDN、无构建）。支持本机绝对路径导入与 zip/7z/rar 压缩包上传，数字键单标签标注、实时保存，每任务可导出完整 CSV 标注表或按标签分目录打包原图与标注表的 ZIP。

## 启动

```bash
cd /home/wanshicong/projects/clsLabelTool
bash start.sh                 # 前台启动（默认端口 8686，CLS_PORT 可覆盖）
```

后台运行（**必须携带 TMPDIR**：Python tempfile 对无效 TMPDIR 会静默回退 /tmp，而根盘已用 99%，spool 大文件必须落在挂载点）：

```bash
cd /home/wanshicong/projects/clsLabelTool
mkdir -p /data_27T_jfs95/wilbur/clsToolData/tmp
TMPDIR=/data_27T_jfs95/wilbur/clsToolData/tmp nohup bash start.sh > /dev/null 2>&1 &
```

`start.sh` 内部已包含 `mkdir -p <挂载点>/tmp` 与 `export TMPDIR`，直接 `bash start.sh` 即满足要求。

## 使用流程

> 界面内顶栏「使用说明」按钮可随时查看完整操作指引（首次使用建议先打开看一遍）。

1. **首次访问**：设置显示名（可跳过；注册时已自动入库默认名「标注员-<id前4位>」，导出 CSV 的 annotatorName 永远非空）。
2. **建任务**（任务列表页）：
   - 来源二选一：**绝对路径**（服务器本机可读的目录；**「包含子文件夹」开关默认勾选=递归扫描全部子目录，取消勾选=仅扫描该目录第一层的图片**；按图片扩展名过滤）或**压缩包上传**（.zip / .7z / .rar，XHR 进度条；100% 后显示「服务器保存中…」——GB 级包 spool+拷贝约 2× 体积写盘，**分钟级等待属正常**）；
   - **标签映射编辑器**：增删类别，顺序即数字热键（前 10 个对应 0-9（第 1 个=0））；**创建后不可修改**（需改标签请删除任务重建）。
3. **标注**（任务卡「打开」）：数字键 **0-9**（第 1 个类别=0）/ 点击类别 → 乐观标注并**立即自动前进到下一张**（当前过滤列表内，最后一张停留提示）；`R` 清除（多张=清空选择）、`a`/`d` 上一张/下一张；`←`/`→` 手动导航（仅单张）；过滤（全部/未标注/已标注）；侧栏分页跳转；侧栏：标签名/灰点、搜索、双击复制文件名；滚轮缩放（单张大图/多张格子内）；**类别按钮右侧显示该类已标张数**。**多张网格模式**（工具栏「单张｜多张」切换，选择记忆）：整屏未标注图片网格，鼠标拖动框选 / Ctrl+点选 / Shift 连选，按 0-9 批量标注，标完的图自动被新未标注图补位。标注**同步写库**后才算保存成功；网络失败自动重试 1 次，仍失败进入顶栏「N 条待重试 + 一键重试」，未确认标注写入 localStorage，**刷新/重新打开页面自动补传**。
4. **导出**：任务卡/标注页工具栏「导出」菜单（仅 ready 可用，未就绪按钮置灰），两种格式：
   - **CSV · 标注表**：浏览器下载完整 CSV，同时在服务器 `exports/` 留档。列：`relPath, absPath, label, labelIndex, annotatorId, annotatorName, updatedAt`（labelIndex=数字类别编号，与热键 0-9 一致；未标注为空）。
   - **ZIP · 图片与标注表**：点击后服务器在 `tmp/` 临时空间构建完整归档（原图不压缩、ZIP_STORED），完成后浏览器自动开始下载，临时文件随即释放（不占 `exports/`）。结构：根目录 `annotations.csv`（与同一快照单独导出的 CSV 内容一致）+ 标签名目录存放原图（保留原数据子目录；未标注统一在 `NOLabel/`；同名图片可同时导出）。为兼容解压环境（如 Windows 设备名/不兼容字符）或消解同名而改动的目录/文件名，记录在根目录 `archivePaths.csv`（`relPath,label,zipPath`，仅存在调整时生成；主 CSV 仍存原始标签与路径，可逐项反查）；源图缺失/打开失败的行保留在 `annotations.csv`，图片跳过，路径与原因列于根目录 `缺失文件.txt`（仅存在缺失时生成）。
   - 导出内容 = 顶栏显示「已保存」的结果（保存中/待重试的标注入库后才含在内）。

## 多终端与任务可见性

- 无账号：身份=浏览器 cookie/localStorage 中的匿名 clientId（uuid）；**换浏览器或清缓存 = 新身份**。
- **任务互相看不见**：任务列表只显示本人创建的任务；他人直接请求你的 taskId/itemId/导出一律 404。
- 「两人标同一批数据」= 各自导入同一路径/压缩包、各建各的任务，各自标注、各自导出完整 CSV。
- **CSV 外部合并**：两人导出 CSV 的 `relPath` 列一致（同一数据源），用 Excel/脚本按 `relPath` 列做 VLOOKUP/JOIN 即可合并两人的 label 列。

## 已知限制

- **仅图片**：jpg/jpeg/png/bmp/webp/gif（v1 不支持文本/音频/视频）；**单标签**（N 选 1）。
- **网格模式加载原图**：无缩略图服务，大图多格首屏加载稍慢（LAN 可接受）；网格固定 6×2=12 张。
- **标签映射创建后不可改**（改标签=删除重建）。
- **任务私有不可共享**（见上）；v1 无跨任务合并导出。
- **压缩包**：不支持**加密**、**分卷**压缩包（error 明确提示）；**不递归解压嵌套压缩包**（见下节）；单包 ≤10GB（超 → 413）；解压实际写出 ≤20GB、成员 ≤20 万（安全护栏，超限中止并提示）。
- **嵌套压缩包现状与临时绕过**：压缩包内的子压缩包（zip/7z/rar）按设计**不递归解压**——若图片全部位于嵌套层，任务会 error「未发现支持的图片文件」（非故障，是设计行为）。典型例子：`潇湘站全站巡视（可见光）.7z` 仅含 3 成员（目录 + xlsx 报告 + 内层 zip），8292 张图片都在内层 zip 里。**临时绕过（二选一）**：
  1. 手动解压一次外层包（任意 7z/解压工具），把内层 zip 所在目录用「绝对路径导入」建任务（内层 zip 本身不会被扫描，但其**解压后的图片目录**会被扫描——即手动把内层 zip 也解压到某目录，然后路径导入该目录）；
  2. 直接「上传内层 zip」（内层是普通 zip，走标准上传流程）。
  是否增加「嵌套压缩包一层递归」能力待产品决策（见 docs/plan/261120_acceptanceRecord.md 待决策项）。
- **删除任务不删物理文件**：任务删除只删数据库记录；uploads 原件、datasets 解压数据保留在磁盘（防误删），需要手动清理（`ls uploads/<uploadId>` 对照任务列表）。
- **exports/ CSV 留档累积**：每次 CSV 导出都在 `exports/` 留档一份，无自动清理（单份 KB 级、量级小），需要时手动删除；服务崩溃可能残留 `.exp-*.tmp` 半成品文件，同样可手动删除。ZIP 不落盘留档（临时文件用后即删）。
- **换浏览器=新身份**（无账号固有）。
- **GB 级上传分钟级等待**（spool+拷贝 2× 体积写挂载点）。
- **服务重启**：重启时处理中（extracting/scanning）任务被置为 error「服务重启导致中断，请删除后重建」，删除后重建即可。
- **卡死任务**：非终态任务可直接删除会 409；可勾选「强制删除」（`?force=true`）中止后台线程并删除；或重启服务。
- **根盘紧张（已用 99%）**：本工具 venv/DB 体积小，大文件均在挂载点；若根盘进一步紧张可 `uv cache clean` 清理 uv 缓存。

## 技术栈

- Python 3.12（uv 管理）：fastapi、uvicorn、python-multipart、libarchive-c（7z/rar 读取，系统 libarchive 3.7.2）
- 前端：原生 HTML + JS + CSS，经典脚本（非 ES module），零外部资源
- SQLite（WAL，本机磁盘）；无测试框架（curl + 原生脚本 + 手工验收）
